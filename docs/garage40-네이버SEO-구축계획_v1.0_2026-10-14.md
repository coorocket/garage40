## 0. 한 장 요약

**지금 상태:** garage40 사이트는 디자인과 문구는 좋지만 **페이지가 딱 1장(index.html)** 이다. 네이버는 "검색어와 정확히 같은 제목을 가진 페이지"를 하나씩 찾아서 보여주기 때문에, 페이지가 1장이면 노출될 수 있는 검색어도 사실상 1~2개뿐이다.

**해야 할 일 한 줄:** "실제 시공 사례 사진을 중심에 두고, 검색어마다 페이지를 하나씩 만들어 네이버에 입구를 늘린다. 성공 기준은 순위가 아니라 **주간 실제 문의 수**다." (bluehelp 전략 그대로)

| 순서 | 할 일 | 왜 필요한가 | 난이도 |
|---|---|---|---|
| 1단계 | 측정 도구 달기 (문의 버튼 클릭 추적) | 효과를 숫자로 보기 위해. 지금은 아무것도 측정되지 않음 | 하 |
| 2단계 | 홈 1장 정리 (제목·H1·스키마·링크 묶음) | 앞으로 만들 페이지들의 "허브" 역할 | 하 |
| 3단계 | 여러 페이지를 만들 수 있게 폴더 구조 바꾸기 | 지금은 1장만 빌드되는 구조 | 중 |
| 4단계 | 시공사례 10편 (실제 전·후 사진) | bluehelp 경험상 **문의를 닫는 건 사례 페이지** | 중 (사진 확보가 관건) |
| 5단계 | 서비스(아이템) 페이지 6~8장 | 지역 없는 대표 검색어용 | 중 |
| 6단계 | 지역 키워드 페이지(/kw/) 1차 6장 → 2차 확대 | 네이버 롱테일 입구 | 중 |
| 7단계 | 사이트맵 2개로 분리·RSS·수집 요청 | 네이버가 새 페이지를 빨리 찾게 | 하 |
| 8단계 | 네이버 밖의 신호 (스마트플레이스·블로그) | 지역 업체는 플레이스가 먼저 보임 | 하 (꾸준함 필요) |
| 9단계 | 6주 측정 후 판정 | 북극성 지표로 계속할지 결정 | 하 |

## 1. 먼저 알아야 할 용어 (10개만)

| 용어 | 쉬운 뜻 |
|---|---|
| SEO | 검색엔진 최적화. 네이버·구글이 우리 페이지를 잘 찾고, 검색 결과 위쪽에 보여주게 만드는 일 |
| 색인(수집) | 네이버가 우리 페이지를 읽어서 자기 창고에 보관하는 것. 색인이 안 되면 아무리 좋아도 검색에 안 나온다 |
| title | 브라우저 탭에 뜨는 제목. 검색 결과의 파란 제목이 보통 이것이다. **네이버 노출에서 가장 중요한 한 줄** |
| H1 | 페이지 본문의 가장 큰 제목 태그. 네이버는 title과 H1이 같은 검색어로 시작할 때 신뢰한다 |
| 완전일치 | 사람이 치는 검색어("시흥 자동차광택")와 title이 글자 그대로 같은 것 |
| 정본 키워드 | 같은 뜻의 여러 표기(자동차광택/차광택/카광택) 중 **검색량이 가장 많은 표기 하나**를 골라 "우리 사이트의 공식 표기"로 정한 것 |
| 롱테일 | "자동차광택"처럼 짧고 경쟁 센 검색어가 아니라 "정왕동 수입차 광택"처럼 길고 구체적인 검색어. 수는 적지만 문의로 이어질 확률이 높다 |
| 사이트맵(sitemap.xml) | 우리 사이트에 어떤 페이지가 있는지 적어 둔 목록 파일. 네이버·구글에 제출한다 |
| 스키마(JSON-LD) | 페이지 안에 "이 업체 이름·전화·주소·서비스는 이것"이라고 기계가 읽기 좋게 적어 둔 숨은 데이터 |
| CTR | 검색 결과에 노출된 횟수 중 실제 클릭된 비율. bluehelp 경험상 2.5%는 낮고, 사례 페이지는 5~27%까지 나왔다 (10/9 측정) |

## 3. bluehelp 전략 8원칙을 garage40 말로 바꾸면

| bluehelp 원칙 | garage40 적용 (제안) |
|---|---|
| 1. Case-first | 새 콘텐츠 1순위는 **시공사례** = 차종·연식·지역 + 전·중·후 사진 + 증상 + 공정 + 소요시간 + 비용 범위 + 전화 버튼 |
| 2. 채널별 정책 분리 | 지역 페이지(/kw/)는 네이버용. 구글에는 사례·서비스 페이지만 적극 색인 요청 |
| 3. 주제 밀도 단위 | 서브도메인은 만들지 않는다. 광택 한 주제이므로 본체 하나로 충분 |
| 4. 키워드 정본 하나 | 정본표를 **스프레드시트 1장**으로 관리 (bluehelp는 DB를 쓰지만 garage40은 정적 사이트라 시트면 충분) |
| 5. 키워드가 title 맨 앞 | 홈만 "GARAGE40 \| …". 나머지 페이지는 브랜드 없이 키워드만 |
| 6. 검색량 ≥ 30 검증 후 생성 | 네이버 검색광고 "키워드 도구"에서 월간 검색수(PC+모바일) 30 이상인 것만 페이지로 만든다 |
| 7. 링크는 위로만, 반복 3~4회 | 사례 → 서비스 → 홈 방향. 지역 페이지끼리 서로 링크 금지 |
| 8. 판정 기간 동결 | 배포한 title·H1은 6주 판정 전까지 바꾸지 않는다 |

**garage40만의 차별점(= bluehelp의 "실제 현장 사진"에 해당):** 40년 장인, 24,000대 기록, 차 한 대마다 다른 진단. 이것을 사례 페이지 문장으로 풀어야 한다. 스톡 사진처럼 보이는 이미지는 사례에 쓰지 않는다.

## 6. 키워드 정본 만들기 (작업 전에 꼭 할 것)

1. 네이버 검색광고(searchad.naver.com)에 가입한다. 광고비를 안 써도 "도구 → 키워드 도구"를 쓸 수 있다.
2. 아래 표기 묶음을 넣고 **월간 검색수(PC+모바일 합)** 를 적는다. 측정일을 같이 적는다.
3. 묶음마다 검색수가 가장 큰 표기를 "정본"으로 정한다. 나머지는 본문·FAQ·이미지 alt에 흩어 쓴다.
4. 결과를 `docs/keyword-canonical.csv` 한 파일로 저장한다. 열: `item_slug, canonical_kw, variants, category, monthly_volume, measured_at`.

| 묶음 (예) | 후보 표기 | 정본 (측정 후 기입) |
|---|---|---|
| car-polish | 자동차광택 / 차광택 / 카광택 / 자동차 광택 | 확인 필요 |
| polish-price | 자동차광택가격 / 자동차광택비용 / 광택가격 | 확인 필요 |

## 7. 단계별 실행 계획

각 단계는 "목적 → 할 일 → 산출물 → 끝났는지 확인하는 법" 순서로 적었다. 위에서부터 차례로 하면 된다.

### 0단계. 준비 (계정·도구) — 반나절

**목적:** 뒤 단계에서 필요한 계정을 미리 만들어 둔다.

| 할 일 | 어디서 | 메모 |
|---|---|---|
| 네이버 서치어드바이저 로그인 확인 | searchadvisor.naver.com | 이미 소유 확인됨. "요청 → 사이트맵 제출"에 sitemap.xml이 들어 있는지 확인 |
| 네이버 검색광고 가입 | searchad.naver.com | 키워드 도구용 (6장) |
| 네이버 스마트플레이스 등록 여부 확인 | smartplace.naver.com | 등록 안 됐으면 사업자등록증·사진으로 등록. 상호는 "GARAGE40 (넘버원카클리닉 K광택)" |
| 네이버 블로그 개설 여부 확인 | blog.naver.com | 사례 글을 올릴 곳 |
| 구글 애널리틱스 4(GA4) 속성 만들기 | analytics.google.com | 측정 ID(G-XXXX) 받아 두기 |
| 네이버 애널리틱스 가입 | analytics.naver.com | 네이버 유입을 더 자세히 보려면. GA4만으로 시작해도 된다 |
| 주간 측정 시트 만들기 | 구글 시트 | 열: 날짜, 노출, 클릭, CTR, 세션, 전화클릭, 카톡클릭, 문자클릭, **실제 문의 수**, 비고 |

**끝 확인:** 위 7개 계정에 모두 로그인되고 시트 1장이 생겼다.

### 1단계. 측정 도구 달기 — 1일

**목적:** "무엇을 바꿨더니 문의가 늘었는지"를 숫자로 보기 위해. 지금은 0이다 (G3).

**할 일**
1. `index.html`의 `</head>` 바로 앞에 GA4 코드를 넣는다.
2. `assets/site.js`에 전화(`tel:`), 카톡(open.kakao.com), 문자(`sms:`) 링크를 눌렀을 때 이벤트를 보내는 코드를 추가한다. 이벤트 이름은 `contact_click`, 매개변수는 `method`(tel/kakao/sms)와 `page_type`(home/category/item/kw/case) 두 개.
3. `page_type`은 각 HTML의 `<body data-page-type="home">`처럼 적어 두고 스크립트가 읽게 한다. 그래야 "어느 종류의 페이지가 문의를 닫는지"를 알 수 있다 (bluehelp 9-1 "page_type 차원").
4. 사장님이 실제로 받은 전화·카톡 수를 **매주 화요일** 시트에 손으로 적는다. 이것이 북극성 지표다.

**산출물:** GA4 실시간 화면에서 `contact_click` 이벤트가 보인다. 시트 첫 줄(기준선)이 채워졌다.

**끝 확인:** 휴대폰으로 사이트에 들어가 전화 버튼을 누르면 GA4 실시간에 `contact_click / method=tel / page_type=home`이 뜬다.

### 2단계. 홈 1장 정리 — 1일

**목적:** 홈을 앞으로 생길 페이지들의 "허브"로 만든다. 동결 규칙 때문에 **이 단계에서 정한 title은 6주간 바꾸지 않는다.**

**할 일**
1. title을 "브랜드 + 광역" 형식으로 바꾼다. 제안: `GARAGE40 | 시흥 자동차광택·도장면 복원 40년`. 지금처럼 지역 5개를 나열하지 않는다. 지역은 /kw/ 페이지가 맡는다.
2. H1은 title과 같은 뜻으로 맞춘다. 제안: `시흥 자동차광택 · 도장면 복원, GARAGE40`. 지금의 `hero-seo-h1`은 글씨가 아주 작은데(0.86rem), 숨김은 아니므로 그대로 두어도 된다. 다만 검색용 H1과 보이는 큰 제목(`hero-title`)을 구분해서 쓴다는 점을 디자인 담당과 합의해 둔다.
3. description은 지금 문장을 유지하되 첫 문장에 "시흥 자동차광택"을 넣는다.
4. 스키마를 보강한다. 지금 AutomotiveBusiness 1개 → `WebSite`, `SiteNavigationElement`를 추가하고, AutomotiveBusiness에 `image`, `areaServed`(시흥·광명·부천·안산·안양·인천), `sameAs`(스마트플레이스·블로그 주소) 를 넣는다.
5. 본문 중간(패키지 섹션 아래)과 푸터에 **"서비스 바로가기" 링크 묶음**을 만든다. 카테고리 3 + 아이템 6~8 + 최신 사례 6개가 들어갈 자리다. 페이지가 아직 없으면 자리만 만들어 두고 3~6단계에서 채운다.
6. OG 이미지(`image/og-garage40.png`, 847KB)는 사례 "after" 사진으로 교체하고 300KB 이하로 줄인다 (bluehelp 3-1 "og는 사례 after 사진").

**산출물:** 수정된 `index.html`. 변경 전·후 title/H1을 시트 "변경 기록" 탭에 날짜와 함께 적는다.

**끝 확인:** 서치어드바이저 "웹 페이지 최적화" 검사에서 title·description·H1이 정상으로 나온다. 네이버 "수집 요청"을 1회 보낸다.

### 3단계. 여러 페이지를 만들 수 있는 구조로 바꾸기 — 1~2일 (개발 필요)

**목적:** 지금 빌드 설정은 `index.html` 1장만 처리한다 (G9). 페이지를 늘리려면 먼저 이걸 고쳐야 한다.

**할 일**
1. 폴더를 만든다. `polish/`, `coating/`, `correction/`, `kw/`, `case/`. 각 페이지는 `폴더/슬러그/index.html` 형태로 둔다. 그러면 주소가 `/kw/siheung-car-polish/` 처럼 끝에 슬래시로 깔끔하게 끝난다.
2. `vite.config.js`에 `build.rollupOptions.input`으로 모든 HTML 파일을 자동으로 찾게 한다. (글로브로 `**/index.html`을 모으는 10줄 정도의 코드. 파일을 추가할 때마다 설정을 고치지 않아도 되게 하는 것이 목적이다.)
3. 공통 머리말(header)·꼬리말(footer)·문의 폼을 **템플릿 1개**로 뽑아 둔다. 방법은 두 가지인데 초보자에게는 (가)를 권한다.
   - (가) `templates/` 폴더에 HTML 조각을 두고, Node 스크립트 `scripts/build-pages.mjs`가 `docs/keyword-canonical.csv`와 `content/*.md`를 읽어 HTML을 생성한다. 페이지 50장을 손으로 복사하지 않아도 된다.
   - (나) 처음 10장까지는 index.html을 복사해서 직접 고친다. 빠르지만 나중에 머리말을 바꾸면 50장을 다 고쳐야 한다.
4. `404.html`을 만든다 (Netlify는 루트의 404.html을 자동으로 쓴다).
5. 각 페이지 `<head>`에 반드시 들어갈 것: 고유 title, description, canonical(자기 주소), og:title/og:image, JSON-LD, `<body data-page-type="…">`.

**산출물:** `pnpm build` 후 `dist/client/` 아래에 폴더별 index.html이 생긴다.

**끝 확인:** 로컬에서 `pnpm dev`로 `/case/테스트/` 주소가 열리고, 배포 후 실제 주소도 열린다. 그 뒤 테스트 페이지는 지운다.

### 4단계. 시공사례 10편 — 2주 (사진 확보가 핵심)

**목적:** bluehelp 경험상 문의를 닫는 건 사례 페이지다 (CTR 5~27%, 10/9 측정). garage40은 지금 0편이다 (G2).

**사례 1편에 들어갈 것 (체크리스트)**
- [ ] 제목: `{지역} {정본} {차종}, {결과}` 예) `시흥 자동차광택 BMW M3 스월마크, 당일 복원`
- [ ] 사진: 전 2장, 과정 1장, 후 2장 이상. **그 차의 실제 사진만.** 다른 사례와 공유 금지
- [ ] 차종·연식·색상, 고객 지역(동 단위까지, 고객 동의 범위에서)
- [ ] 증상(스월마크·홀로그램·오렌지필 등)과 장인의 진단 한 문단
- [ ] 적용 프로그램(스탠다드/BEST/VIP), 공정 요약(세차·진단 → 폴리싱 단계 → 코팅·검수)
- [ ] **작업 개요 표:** 소요 시간, 투입 인원, 사용 단계 수, 비용 범위(예: 30~35만원). 이 표는 HowTo 스키마로도 넣는다 (AI 검색 대비, bluehelp 3-2 AEO)
- [ ] 본문 중간에 전화·카톡 버튼 1회, 하단에 1회
- [ ] 해당 아이템 페이지(예: 스월마크제거)로 가는 링크 1개, 카테고리 링크 1개
- [ ] 사진 alt에 정본 키워드 + 차종

**사진이 당장 10편 분량이 없다면:** 앞으로 들어오는 차량마다 전·중·후를 찍는 루틴을 먼저 만든다 (휴대폰, 같은 조명 위치, 같은 각도). 주 2~3대만 찍어도 한 달이면 10편이다.

**산출물:** `/case/…/` 10장, 홈 "최신 사례 6" 영역이 실제 링크로 채워짐.

**끝 확인:** 서치어드바이저 "수집 요청"으로 10개 URL을 넣었고, 1~2주 뒤 "사이트 진단 → 색인 현황"에 잡힌다.

### 5단계. 아이템(서비스) 페이지 6~8장 — 1주

**목적:** "자동차광택", "유리막코팅"처럼 지역 없는 대표 검색어용 페이지. bluehelp는 이 레이어의 1위가 0에서 6~8을 목표로 했다 (9-4).

**할 일 (페이지 1장마다)**
1. title = 정본 키워드만 (브랜드 없음). H1 동일.
2. description = "시흥·광명·부천·안산·안양 출장 없이 시흥 금오로 매장 시공 + 전화번호" 식으로 지역과 연락처를 넣는다.
3. 본문 8섹션 (bluehelp 5-1): ① 히어로(한 줄 설명 + 가격 시작가) ② 사례 3세트(전·후) ③ 핵심 포인트 ④ 고유 문단 4개(이 서비스에서 장인이 보는 것, 흔한 실패 사례, 차종별 차이, 유지 관리) ⑤ 관련 서비스 ⑥ FAQ 5개 ⑦ 함께 보기(사례 목록) ⑧ 문의 CTA.
4. 스키마 6종: Service, BreadcrumbList, ItemList, AutomotiveBusiness, FAQPage, ImageGallery.
5. 글자 수 목표 3,000자 이상. **지역명만 바꾼 복사 문단 금지.**

**끝 확인:** 6~8장이 홈 허브 링크·카테고리 페이지에서 모두 연결된다. 각 페이지에 사례에서 들어오는 링크가 3개 이상 있다.

### 6단계. 지역 키워드 페이지(/kw/) — 1차 6장 (1주), 2차 20~30장 (검색량 확인 후)

**목적:** 네이버 롱테일 입구. bluehelp에서 가장 잘 먹힌 레이어(1위 72개, 10/9 측정).

**할 일**
1. 1차는 `{시·구} × 자동차광택` 6장만 만든다: 시흥·광명·부천·안산·안양·인천.
2. title/H1 = `{지역} {정본}` 완전일치. 예) `광명 자동차광택`.
3. 본문: 해당 지역 고객 사례 요약 2~3개(4단계 사례에서 가져옴) + 오시는 길(해당 지역에서 금오로 499까지 거리·시간) + 가격 표 + FAQ 3 + CTA. 지역명만 바꾼 틀 문장은 네이버에는 통해도 구글이 싫어하므로 사례 요약으로 차이를 만든다.
4. 링크: 이 페이지 → 아이템(자동차광택) → 카테고리 → 홈. **아이템에서 이 페이지로 되돌아오는 링크는 넣지 않는다. 지역 페이지끼리도 링크하지 않는다.** 발견은 사이트맵과 SiteNavigationElement가 맡는다.
5. 2차(생활권 지명, 다른 아이템 × 지역)는 6장 정본표에서 검색량 30 이상 확인된 것만 만든다.

**끝 확인:** 6장 모두 `sitemap-kw.xml`에 들어 있고, 2주 뒤 순위 확인 시트에 "시흥 자동차광택" 등 6개 검색어의 순위가 기록된다.

### 7단계. 사이트맵 분리·RSS·수집 요청 — 반나절

**목적:** 네이버가 새 페이지를 빨리, 빠짐없이 찾게 한다 (G6).

| 할 일 | 내용 |
|---|---|
| 사이트맵 2개로 분리 | `sitemap-core.xml`(홈·카테고리·아이템·사례) + `sitemap-kw.xml`(지역 페이지). `sitemap.xml`은 두 파일을 가리키는 인덱스로 바꾼다 |
| 어디에 제출 | **네이버에는 둘 다, 구글 서치콘솔에는 core만** (bluehelp 7장 확정) |
| 이미지 사이트맵 | `sitemap-images.xml`에 사례·아이템 전후 사진을 넣고 image:title에 정본 키워드. robots.txt에 선언 |
| lastmod | 실제 바뀐 날짜만 쓴다. 날짜만 갱신하는 꼼수는 bluehelp에서도 "결정 대기"이므로 하지 않는다 |
| RSS | `rss.xml`에 사례 최신 20편. 서치어드바이저 "RSS 제출"에 등록 (네이버는 RSS도 받는다) |
| 수집 요청 | 새 페이지는 서치어드바이저 "웹 페이지 수집"에 하루 최대 50건 요청. 생성 즉시 하는 습관 |
| 빌드 자동화 | 3단계의 생성 스크립트가 사이트맵·RSS도 같이 만들게 한다. 손으로 고치면 반드시 빠뜨린다 |

**끝 확인:** 서치어드바이저 사이트맵 메뉴에 3개 파일이 "정상"으로 보인다.

### 8단계. 네이버 밖의 신호 — 매주 반복

**목적:** 지역 업체 검색("시흥 광택")은 웹 문서보다 **플레이스와 블로그**가 먼저 보인다. 사이트만 좋아서는 안 된다 (G8).

| 할 일 | 주기 | 메모 |
|---|---|---|
| 스마트플레이스 정보 완성 | 1회 | 사진 20장 이상, 가격표(15/30/50), 영업시간, 홈페이지 주소 = garage40 사이트, 예약·톡톡 연결 |
| 플레이스 "소식"에 사례 요약 올리기 | 주 1회 | 사이트의 사례 페이지 링크 포함 |
| 네이버 블로그 사례 글 | **주 2건** | 사이트 사례와 같은 차량이어도 글은 새로 쓴다. 본문에 해당 사례 페이지와 아이템 페이지 링크 1개씩 (bluehelp 3-1 "하위 URL 링크 글 주 2건") |
| 리뷰 요청 | 시공 때마다 | 플레이스 영수증 리뷰. 사이트 사례 페이지에 리뷰 문장 인용 |
| 홈 스키마 `sameAs` | 1회 | 플레이스·블로그 주소를 넣어 같은 업체임을 알린다 |

**끝 확인:** "시흥 자동차광택" 검색 시 플레이스 영역에 GARAGE40이 뜨고, 블로그 글에서 사이트로 유입이 GA4에 잡힌다.

### 9단계. 측정과 판정 — 6주 후

**지표 (bluehelp 9-1 그대로)**

| 구분 | 지표 | 어디서 보나 |
|---|---|---|
| 북극성 | 주간 실제 문의 수 (전화 + 카톡 + 문자) | 사장님이 시트에 직접 기록 |
| 보조 | 네이버 노출·클릭·CTR | 서치어드바이저 "검색 노출 통계" |
| 보조 | 유효 1위 = 1위이면서 월 검색량 ≥ 30 | 순위는 네이버에서 직접 검색(시크릿 창), 검색량은 정본표 |
| 보조 | 사례 페이지 CTR, `contact_click`의 page_type별 비율 | GA4 |

**기준선:** 1단계가 끝난 주의 숫자를 "0주차"로 적는다. 기준선 없이 시작하면 판정이 불가능하다.

**6주 목표 (제안, bluehelp 9-4 비율을 참고해 작게 잡음)**

| 레이어 | 목표 |
|---|---|
| 아이템 (지역 없는 대표 키워드) | 1위 또는 첫 화면 2개 이상 |
| /kw/ 1차 6장 | 첫 화면 노출 4개 이상 |
| 사례 10편 | 합산 클릭이 홈 클릭을 넘어섬 |
| 북극성 | 주간 실제 문의 수가 기준선의 2배 |

**동결 규칙:** 판정일 전에는 배포한 title·H1·스키마를 바꾸지 않는다. 디자인 수정이 필요하면 검색용 H1(작은 글씨)과 보이는 제목(큰 글씨)을 구분해 보이는 쪽만 고친다.

## 8. 하지 말아야 할 것 (bluehelp "비채택" + garage40 추가)

## 11. 부록

### 11-1. 페이지 1장의 뼈대 (아이템·kw·사례 공통)

```html
<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>광명 자동차광택</title>                       <!-- 정본 키워드만, 브랜드 없음 -->
  <meta name="description" content="광명에서 20분, 시흥 금오로 GARAGE40. 40년 장인이 직접 진단·시공. 스탠다드 15만원부터. 010-4684-8838">
  <link rel="canonical" href="https://garage40.netlify.app/kw/gwangmyeong-car-polish/">
  <meta property="og:title" content="광명 자동차광택">

  <link rel="stylesheet" href="/assets/styles.css">

</head>
<body data-page-type="kw">
  <!-- 공통 header -->
  <main>
    <h1>광명 자동차광택</h1>                             <!-- title과 같게 -->

  <script type="module" src="/assets/site.js"></script>

</html>
```

### 11-2. 문의 클릭 이벤트 (1단계) 동작 설명

1. 사용자가 `tel:`, `sms:`, `open.kakao.com` 링크를 누른다.
2. `site.js`가 클릭을 가로채 GA4에 `contact_click` 이벤트를 보낸다. 값은 `method`(tel/sms/kakao), `page_type`(body의 data 속성), `page_path`.
3. GA4 "탐색" 보고서에서 page_type별 contact_click 수를 본다. 사례 페이지가 가장 많으면 bluehelp와 같은 패턴이다.

### 11-3. 매주 화요일 10분 루틴

1. 서치어드바이저 → 검색 노출 통계 → 지난 7일 노출·클릭을 시트에 적는다.
2. 네이버 시크릿 창에서 추적 키워드(처음엔 15개)를 검색해 순위를 적는다.
3. GA4에서 contact_click 합계와 page_type별 수를 적는다.
4. 사장님이 실제 문의 수를 적는다.
5. 새로 만든 페이지 URL을 "웹 페이지 수집"에 요청한다.
