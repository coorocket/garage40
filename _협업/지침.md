## Aside 협업 규칙 (_협업/ 폴더)
- 사용자가 "to_code 확인"이라고 하면 `_협업/to_code/*.md` 중 `## 결과` 섹션이 없는 파일을 날짜순으로 모두 처리한다.
- 처리: 요청서의 "할 일"만 구현한다. 요청서에 없는 변경 금지. "금지" 목록 위반 금지. 다른 저장소 수정 금지.
- 작업은 새 브랜치(접두어: 요청서의 커밋 접두어)에서 하고 PR을 만든다. **main 직접 push·병합 금지.** 사용자가 머지한다.
- 끝나면 (1) 요청서 끝에 `## 결과`(PR 번호·변경 파일·자체검증 표·못 한 것)를 적고 `_협업/done/`으로 이동, (2) `_협업/to_aside/YYYYMMDD-HHMM_제목.md`에 같은 내용의 결과 메모를 만든다. 둘 다 같은 PR에 포함한다.
- 오류: 2회 스스로 고쳐 보고, 3번째에 멈춰서 `_협업/to_aside/`에 원인과 A(안전)/B(근본)/C(보류) 3가지 선택지를 적는다.
- 검색 노출에 영향 주는 변경(URL·title/meta·sitemap·robots·canonical·noindex·리다이렉트·템플릿)은 요청서의 사전검토 표가 있어야만 진행한다. 없으면 멈추고 묻는다.
- 요청서·결과 메모에 전화번호·주소·토큰 등 개인정보를 쓰지 않는다.

# Aside ↔ Claude Code(깃허브 클라우드) 협업 프로토콜 v2 (2026-10-16)

## 한 줄 원칙
**요청서와 결과는 전부 저장소 안 `_협업/` 폴더에 둔다.** 로컬 폴더가 아니라 GitHub가 유일한 기준이다. 클라우드 세션은 저장소만 볼 수 있기 때문이다.

## 폴더 (저장소마다 동일)
```
_협업/
  to_code/   Aside → Claude Code 요청서 (YYYYMMDD-HHMM_제목.md)
  to_aside/  Claude Code → Aside 결과 메모
  done/      양쪽이 끝낸 파일
```
- 공개 저장소(cmdlab·jstars·garage40)에도 두되, 요청서에 전화번호·개인정보·토큰을 쓰지 않는다. 필요하면 "Vault 항목명"으로만 적는다.
- Workers 사이트(bluehelp 4개)에서는 `_협업/`가 배포 자산(public/)에 들어가지 않게 둔다(저장소 루트).

## 누가 무엇을 (역할표)
| 단계 | Aside | 사장님 | Claude Code(클라우드) |
|---|---|---|---|
| 1 요청 | `_협업/to_code/`에 요청서 커밋(사전검토 표·금지목록·완료기준 포함) | — | — |
| 2 호출 | — | 해당 저장소 클라우드 세션에 **"to_code 확인"** 입력 | `to_code/`에서 `## 결과`가 없는 파일을 전부 읽고 처리 |
| 3 구현 | — | — | 새 브랜치 → 커밋 → **PR 생성**(병합 금지). 요청서 끝에 `## 결과` 추가하고 `done/`으로 이동. `to_aside/`에 결과 메모 작성(같은 PR 안에) |
| 4 검토 | PR 파일·결과 메모를 읽고 리뷰. 수정 필요하면 `to_code/`에 "…_수정1.md" 추가 | — | 수정 요청 처리 후 같은 PR 갱신 |
| 5 반영 | — | **PR 머지**. Workers 사이트는 로컬에서 `git pull` → `npm run deploy` 후 Aside에 "배포했다" | — |
| 6 사후검증 | 15분 내 라이브 검증(seo-change-guard C) → 결과를 `to_aside/` 메모에 `## 결과`로 적고 `done/` 이동, 프로젝트 MEMORY 기록 | — | — |

## 신호어
- 사장님 → Claude Code: **"to_code 확인"** (저장소별 세션)
- 사장님 → Aside: **"협업확인"** → Aside가 7개 저장소의 열린 PR과 `_협업/to_aside/`를 전부 훑어 표로 보고
- 사장님 → Aside: **"배포했다 {사이트}"** → 사후검증 시작

## Aside가 GitHub에 쓰는 방법 (둘 중 하나, 사장님 선택)
- **방법 1(추천)**: GitHub 세분화 토큰(Fine-grained PAT). 권한: 저장소 7개 한정, Contents 읽기/쓰기, Pull requests 읽기, 만료 90일. Aside Vault에 "GitHub Aside PAT"로 저장. Aside는 REST API로 파일 생성·이동·PR 읽기. (가장 빠르고 안정적)
- **방법 2(대안)**: Aside가 로그인된 브라우저로 github.com 웹 편집기에서 파일 생성·커밋. 토큰 불필요, 대신 느리고 파일당 스냅샷 비용.

## 요청서 형식 (필수 항목)
```
# [사이트] 제목
- 요청자 / 대상 저장소 / 사장님 승인일 / 브랜치 접두어(seo:, design:, perf:)
## 왜
## 할 일 (번호)
## 금지
## 완료 기준 (Claude Code 자체검증 항목)
## 사전검토 표 (seo-change-guard) + 3줄(구글/네이버/URL)
```
클라우드가 끝내면 같은 파일 끝에:
```
## 결과
- PR: #번호, 브랜치
- 변경 파일:
- 자체검증 결과 표:
- 못 한 것 / 판단 필요:
```

## 오류·막힘 규칙 (하네스)
Claude Code는 2회 자가수정 후 3번째에 멈추고 `to_aside/`에 원인 + A(안전)/B(근본)/C(보류) 3선택지로 보고. 다른 저장소 수정·URL 삭제·스키마 삭제는 즉시 중단.

## 로컬 `_협업/` 폴더는?
Aside의 기록용 사본으로만 유지(각 저장소 `_협업/`를 주기적으로 내려받음). 사장님은 더 이상 로컬 폴더를 볼 필요 없음.

## 클라우드로 할 수 없는 일 (로컬 Claude Code 또는 Aside 담당)
- 맥에서 돌아가는 도구(문자 자동전달 sms-relay 등)
- `npm run deploy`(Cloudflare 배포)
- D1 데이터·어드민 입력
